# 季度RP检查清单 - 快速参考

> 本文档提供季度立项评审的快速检查表，可用于评审现场逐项核对。

---

## 📋 检查清单总览

| 检查项 | 负责人 | 检查点数量 | 关键级别 |
|--------|--------|------------|----------|
| 一、特性列表规范度 | PO | 5 | 🔴 高 |
| 二、特性规划文档 | PO | 2 | 中 |
| 三、用户故事列表 | SM | 4 | 中 |
| 四、资源维护 | SM | 1 | 中 |
| 五、资源负荷 | SM | 2 | 中 |

---

## 🔴 第一部分：特性列表规范度（PO负责）

```
□ 1. 特性状态标记正确（至少规划完成）
□ 2. Release字段设置正确
□ 3. 确认特性一次性发布完成，不拆分
□ 4. P0级特性规划报告已输出并评审通过
□ 5. P0级特性设计报告已识别勾选（迭代中输出）
```

**🔴 红色警示项：**
- 特性状态必须正确，否则无法立项
- P0级特性设计报告必须在迭代中完成

---

## 📄 第二部分：特性规划文档（PO负责）

```
□ 1. 需要规划文档的特性已准备PPT/WORD格式
□ 2. 文档已放入VSS对应目录
```

---

## 📝 第三部分：用户故事列表（SM负责）

```
□ 1. 缺陷转用户故事的需求（性能、安全等）已立项
□ 2. 迭代阶段在当前季度Release范围内（如4月迭代一~6月迭代二）
□ 3. 目标状态设置为"发布完成"
□ 4. 80%的用户故事估算 ≤ 10人天
```

---

## 👥 第四部分：资源维护（SM负责）

```
□ 1. DMP项目组资源维护已完成
```

---

## 📊 第五部分：资源负荷（SM负责）

```
□ 1. 资源负荷达到 90~100%（涵盖总体、需求、开发、测试及整体）
□ 2. 已通过DMP项目看板验证
```

**负荷标准：**
- 推荐范围：90%~100%
- 检查对象：领域总体、需求、开发、测试、项目组整体

## 📞 评审现场问题处理

| 问题 | 处理方案 | 责任人 |
|------|----------|--------|
| 特性状态不正确 | 立即在金蝶系统中修正 | PO |
| P0规划报告缺失 | 补充规划报告并重新评审 | PO |
| 故事粒度超标 | 拆分用户故事或调整评估 | SM |
| 负荷率<90% | 增加特性或优化资源分配 | SM |
| 负荷率>100% | 减少特性或申请增加资源 | SM |

---

## 💡 最佳实践

1. **提前自检**：评审前至少1天，PO和SM各自完成负责项的自检
2. **证据留存**：所有文档归档路径、看板截图、计算表格需保留
3. **争议预案**：提前准备负荷调整、特性裁剪的备选方案
4. **评审效率**：使用本检查清单快速对照，逐项打勾确认
