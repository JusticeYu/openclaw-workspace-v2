## 📋 完整使用流程（推荐）

以下是一个完整的季度立项流程示例：

### 第1步：计算季度工作日

**场景**：计算2026年第二季度工作日

```bash
python scripts/workday_calculator.py --year 2026 --quarter 2
```

**输出示例：**
```
==================================================
2026年第二季度工作日计算
==================================================
📅 日期范围：2026-04-01 至 2026-06-30
📊 总天数：91天
🌴 周末：18天
🎉 节假日：11天
💼 补班：3天
✅ 工作日：62天
```

**记录数据**：
- 季度工作日：**62天**

---

### 第2步：维护项目组成员系数

**创建成员配置文件**：

```json
// references/members_Q2_2026.json
[
  {"name": "张三", "role": "dev", "capacity": 0.8},
  {"name": "李四", "role": "dev", "capacity": 1.0},
  {"name": "王五", "role": "dev", "capacity": 1.0},
  {"name": "赵六", "role": "test", "capacity": 0.8},
  {"name": "孙七", "role": "test", "capacity": 0.7},
  {"name": "周八", "role": "product", "capacity": 0.5},
  {"name": "吴九", "role": "product", "capacity": 0.3}
]
```

**计算各角色系数总和**：
- 开发系数总和：0.8 + 1.0 + 1.0 = **2.8**
- 测试系数总和：0.8 + 0.7 = **1.5**
- 产品系数总和：0.5 + 0.3 = **0.8**

---

### 第3步：评估项目组负荷

**场景**：计划总人天为180天

```bash
python scripts/capacity_calculator.py \
  --workdays 62 \
  --dev-capacity 2.8 \
  --test-capacity 1.5 \
  --product-capacity 0.8 \
  --total-days 180
```

**输出示例：**
```
============================================================
📊 项目组负荷评估报告
============================================================

【基础参数】
  季度工作日：62天
  开发系数：2.8
  测试系数：1.5
  产品系数：0.8
  系数总和：5.1

【产能分析】
  总可用产能：316.2 人天
  计划人天：180.0 人天
  剩余产能：136.2 人天

【负荷评估】
  负荷率：56.9% ⚡ (偏低)
  建议范围：70% - 85%
  评估建议：负荷较低，有空间增加特性
============================================================
```

**⚠️ 重要**：根据检查清单，负荷率应达到 **90-100%**！
- 当前56.9%偏低，需要**增加特性或优化资源分配**

---

### 第4步：特性优先级排序

使用 **MoSCoW 方法**对候选特性排序：

| 优先级 | 说明 | 示例 |
|--------|------|------|
| Must | 必须在本季度完成 | 核心业务功能 |
| Should | 应该完成，有灵活性 | 重要的用户体验优化 |
| Could | 可以完成，资源允许时 | 辅助功能、小优化 |
| Won't | 明确排除，放入 backlog | 非核心需求 |

**在金蝶系统中标记特性状态和优先级**

---

### 第5步：用户故事拆分

**拆分原则**：
- 每个故事应可独立交付价值
- **80%的用户故事估算 ≤ 10人天**（检查清单要求）
- 遵循 INVEST 原则

**人天评估示例**：

| 故事ID | 故事描述 | 开发人天 | 测试人天 | 需求人天 | 总人天 |
|--------|----------|----------|----------|----------|--------|
| STORY-001 | 用户登录优化 | 5 | 2 | 1 | 8 |
| STORY-002 | 性能优化 | 8 | 3 | 1 | 12 |
| STORY-003 | 安全加固 | 6 | 2 | 1 | 9 |
| STORY-004 | 报表功能 | 4 | 1.5 | 0.5 | 6 |

**总计划人天**：8 + 12 + 9 + 6 = **35人天**

---

### 第6步：重新评估负荷

**更新后的总人天**：假设最终确定为 **300人天**

```bash
python scripts/capacity_calculator.py \
  --workdays 62 \
  --dev-capacity 2.8 \
  --test-capacity 1.5 \
  --product-capacity 0.8 \
  --total-days 300
```

**输出示例：**
```
负荷率：94.9% ✅ (合理)
建议范围：90% - 100%
评估建议：负荷在建议范围内，状态良好
```

**✅ 满足检查清单要求（90-100%）**

---

### 第7步：生成规划报告PPT

```bash
python scripts/create_ppt_template.py --output Q2_2026_planning.pptx
```

**生成的PPT包含8页**：
1. 封面
2. 目录
3. 季度目标与策略
4. 特性规划
5. 资源与负荷分析
6. 里程碑与关键节点
7. 风险与应对措施
8. 结束页

**填充PPT内容**：
- 使用计算得到的工作日、负荷率数据
- 填入特性清单、用户故事列表
- 标注里程碑时间点
- 列出风险和应对措施

---

### 第8步：立项评审检查

**使用检查清单逐项核对**（见 `rp_checklist_quickref.md`）

```
□ 1. 特性状态标记正确（至少规划完成）
□ 2. Release字段设置正确
□ 3. 确认特性一次性发布完成
□ 4. P0级特性规划报告已输出并评审通过
□ 5. P0级特性设计报告已识别勾选
□ 6. 需要规划文档的特性已准备PPT/WORD
□ 7. 文档已放入VSS对应目录
□ 8. 缺陷转用户故事的需求已立项
□ 9. 迭代阶段在当前季度Release范围内
□ 10. 目标状态设置为"发布完成"
□ 11. 80%的用户故事估算 ≤ 10人天
□ 12. DMP项目组资源维护已完成
□ 13. 资源负荷达到 90~100%
□ 14. 已通过DMP项目看板验证
```

**评审通过后，立项完成！** 🎉

## ❓ 常见使用问题

**Q：如何选择季度？**
A：`--quarter 1/2/3/4`，1=一季度(1-3月)，2=二季度(4-6月)，3=三季度(7-9月)，4=四季度(10-12月)

**Q：负荷率怎么调到90-100%？**
A：增加特性（提高总人天）或减少资源（降低系数总和）

**Q：P0级特性是什么？**
A：最高优先级的特性，必须输出规划报告，设计报告在迭代中输出

**Q：如何处理负荷率超过100%？**
A：必须调整立项范围，减少低优先级特性，或申请增加资源

**Q：金蝶系统没有API怎么办？**
A：当前版本需要手工导出/导入数据，后续可对接API实现自动化
